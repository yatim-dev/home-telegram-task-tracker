# Home Telegram Task Tracker Bot

Телеграм-бот для домашних дел и задач: **администратор** назначает задачи пользователям, бот присылает напоминания, пользователи отмечают выполнение и получают **монетки** (баланс). Есть **роли**, **регистрация по одноразовому ключу** и **история выполнений**.

## Возможности

- **Роли**: `admin` и `user`
- **Регистрация по одноразовому ключу** с **датой истечения**
- **Назначение задач** админом пользователям по `@username`
- **Повторяющиеся задачи** и разовые:
  - `once`, `daily`, `weekly`, `every:Nd`, `every:Nw`
- **Напоминания** (проверка раз в минуту)
- **Монетки** за выполнение задач + баланс
- **История выполнений** (`/history`)
- **Админ-управление задачами**: редактирование (`/edit`), удаление (`/delete`)

## Первичный админ (bootstrap)

Команда `/genkey` доступна только администратору. Поэтому первого админа нужно назначить вручную.

Напишите боту:
```commandline
/whoami
```

Скопируйте свой ID.

Откройте SQLite файл tasks.db (например, DB Browser for SQLite) и выполните:

```oracle-sql
UPDATE users
SET is_active = 1,
    role = 'admin',
    registered_at = datetime('now')
WHERE user_id = <ВАШ_ID>;
```
Перезапустите бота.

Теперь вы сможете создавать ключи и назначать задачи.

## Роли и доступы
### user

    может только:
        смотреть задачи (/tasks)
        выполнять (/done)
        смотреть баланс (/balance)
        смотреть историю (/history)

### admin

    может всё как user +
        создавать ключи (/genkey)
        смотреть пользователей (/users)
        назначать задачи (/addto)
        добавлять задачи себе (/add)
        редактировать задачу (/edit)
        удалять задачу (/delete)

## Команды
### Команды для всех
`/start [ключ]`

Регистрирует пользователя в базе (создаётся “черновик”).
Если указан ключ: пытается активировать пользователя.

Примеры:
```commandline
/start AbCDeF_123
```


`/help [раздел]`

Открывает справку с кнопками. Возможные разделы:

`commands`, `examples`, `reminders`, `faq`, `about`, `admin` (последний только для админа)

Примеры:
```commandline
/help
/help commands
/help admin
```

`/whoami`

Показывает профиль:

    user_id
    username
    роль
    активность
    баланс

## Команды пользователя (user)

Все команды ниже работают только после активации ключом.

`/tasks`

Показывает список активных задач пользователя.

Формат вывода обычно:

    id. текст
    ⏰ next_due
    🔁 период
    💰 награда

Пример
```commandline
/tasks
```

`/done <task_id>`

Отмечает задачу выполненной и начисляет монетки.

Важно:

для once задача закрывается (исчезает из /tasks)
для повторяющихся (daily, weekly, every:Nd) задача переносится на следующий срок (в /tasks останется, но с новой датой)

```commandline
/done 3
/done 12
```

`/balance`

Показывает текущий баланс монет.

Пример:

```commandline
/balance
```

`/history [N]`

Показывает историю выполнений (по умолчанию 20 записей).
N можно от 1 до 100.

Примеры:
```commandline
/history
/history 50
```

## Команды администратора (admin)
`/genkey <user|admin> <YYYY-MM-DD_HH:MM>`

Создаёт одноразовый ключ регистрации с истечением.

Примеры:

```commandline
/genkey user 2026-01-10_12:00
/genkey admin 2026-01-10_12:00
```

Пользователь активируется так:
```commandline
/start <ключ>
# или
/register <ключ>

```

`/users`

Показывает список пользователей:

    id, username
    роль, активность
    баланс

Пример:

```commandline
/users
```

`/add <...>`

Добавляет задачу самому админу (как пользователю).

Форматы см. ниже в разделе Форматы задач и периодичность.

Примеры:

```commandline
/add Помыть посуду 18:30 10
/add Сдать проект 2026-01-10 12:00 50 once
```

`/addto @username <...>`

Назначает задачу пользователю по @username.

Важно:

пользователь должен хотя бы раз написать боту (/start), чтобы @username попал в таблицу users.

Примеры:

```commandline
/addto @vasya Помыть посуду 18:30 10
/addto @vasya Протереть пыль 2026-01-03 18:00 5 every:3d
```

После назначения пользователю отправляется уведомление: “Вам назначена новая задача”.

`/edit <task_id> <...>`

Редактирует задачу по task_id. Формат задачи как в /add.
Также сбрасывает last_notified_due, чтобы напоминания работали корректно.

Примеры:

```commandline
/edit 12 Помыть посуду 19:00 10
/edit 12 Протереть пыль 2026-01-05 18:00 7 every:3d
```

`/delete <task_id>`

Удаляет задачу полностью.

Где взять task_id:

в `/tasks` первая цифра строки — это id.

Пример:

```commandline
/delete 12
```

Важно:

удаляет задачу из tasks история выполнений (/history) не удаляется

## Форматы задач и периодичность

Поддерживаются 2 формата:
### 1) Без даты (по умолчанию ежедневная)

```commandline
/add <текст> <ЧЧ:ММ> <монетки> [daily|weekly|every:Nd]
```

Пример:
```commandline
/add Помыть посуду 18:30 10
```

Если время сегодня уже прошло — задача ставится на завтра.
### 2) С датой

```commandline
/add <текст> <YYYY-MM-DD> <ЧЧ:ММ> <монетки> [once|daily|weekly|every:Nd]
```

Примеры:

```commandline
/add Сдать проект 2026-01-10 12:00 50 once
/add Полить цветы 2026-01-03 09:00 2 daily
/add Протереть пыль 2026-01-03 18:00 5 every:3d
```

Периодичность
```commandline
once — разовая задача
daily — каждый день
weekly — каждую неделю
every:Nd — каждые N дней (например every:3d)
every:Nw — каждые N недель (например every:2w)
```

## Напоминания

Бот проверяет задачи примерно раз в минуту

Напоминание отправляется, если next_due совпадает с текущей минутой YYYY-MM-DD HH:MM
Чтобы не спамить, после отправки ставится last_notified_due и в ту же минуту повторное сообщение не уйдёт
Часовой пояс берётся с машины/сервера, где запущен бот

### История выполнений

Каждый `/done` создаёт запись в истории:

    task_id, текст задачи
    монетки
    время выполнения
    assigned_by (если задачу назначал админ)

Команда:

```commandline
/history [N]
```

### База данных

SQLite файл: tasks.db

Основные таблицы:

    users — пользователи, роли, активность, баланс
    registration_keys — одноразовые ключи регистрации с истечением
    tasks — задачи (назначение пользователю, повтор, next_due)
    task_completions — история выполнений

### Оптимизация:

    WAL + индексы
    DB операции выполняются в отдельном потоке (AsyncDB), чтобы бот не зависал

## Частые проблемы
### Message is not modified

Иногда возникает при нажатии на help-кнопки повторно (когда текст не меняется).
В проекте рекомендуется обрабатывать BadRequest и игнорировать это сообщение.
database is locked

    убедитесь, что не запущено 2 копии бота
    закройте инструменты, которые открыли tasks.db
    иногда помогает остановить бота и удалить tasks.db-wal и tasks.db-shm

### Не находится пользователь по @username

    пользователь должен хотя бы один раз написать боту /start
    username должен быть установлен в Telegram
